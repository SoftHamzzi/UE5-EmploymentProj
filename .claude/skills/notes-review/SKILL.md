Notes 문서(`DOCS/Notes/**`, `DOCS/Mine/**`) 작업을 마칠 때 이 체크리스트를 스스로
돈다. 사용자가 매번 "검토해봐"라고 요청하지 않아도 기본으로 한다.

## 1. 자체 점검 (`CLAUDE.md` §1-4 기준)

- **정확성** — 코드/엔진 소스를 실제로 대조했는가, 추측을 사실처럼 쓰지 않았는가.
  파일:줄 인용이 있으면 방금 다시 읽어서 맞는지 확인한다.
- **확장성** — 문서에 이름 붙은 확장점만 다뤘는가(§2 "상상 속 확장점" 없음).
- **수술적 변경** — 요청 범위 밖 내용을 안 건드렸는가, 기존 스타일과 맞는가.
- **간결성** — 과정(시행착오, 뒤집힌 결정, 외부 검토 왕복)이 아니라 **현재 상태와
  그 근거만** 남겼는가 — 특히 STATUS류 문서. "왜 이렇게 됐는가"는 한두 줄로 족하다.

## 2. 외부 리뷰가 필요한가 판단

아래 중 하나라도 해당할 때만 `Notes/<영역>/Review/`에 REVIEW 요청 문서를 만든다.
아니면 그냥 진행한다 — **루틴으로 만들지 않는다.**

- 설계 판단이 여러 방향으로 갈리고 스스로 확신이 안 서는 경우
- 되돌리기 비싼 결정(자료구조, 식별자 안정성, 네트워크 계약)인데 검증 근거가 약한 경우
- 사용자가 명시적으로 검토를 요청한 경우

확신이 서면 리뷰를 만들지 말고 그냥 진행하고, 근거만 문서에 남긴다.

## 3. 외부 리뷰 답변이 이미 있을 때

`Review/*_Answer.md`가 이미 존재하면 그 내용을 그대로 설계에 반영하지 않는다 —
`review-verifier` 서브에이전트에 위임해서 각 주장을 실제 코드/엔진 소스로 대조
검증한 뒤, CONFIRMED된 것만 반영한다.
